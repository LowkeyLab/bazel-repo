# Public command schemas, version 1

This inventory covers the installed command-line tool. [README.md](README.md)
explains selectors, authority, cooperative ownership, recovery, and retention.
Types and nullable/omitted alternatives describe actual version-1 receipts.

## Envelope, primitives and error variants

- Every ordinary `JSON` command result is one newline-terminated object: `schema_version` integer 1, `command` string, `outcome` completed/rejected/pending/unknown, `reason_code` string, `context` object, `data` object, `warnings` string array.
- Exit 0 completed. 2 rejected. 3 pending. 4 unknown. Broken result write returns 4 and direct stderr `result_output_failed`. A committed operation isn't undone. Help/version exit 0 use clap display output, not the envelope. Malformed `JSON`-mode arguments use command `parse`, rejected/`invalid_arguments`, context `{}`, data `{next_action}`.
- `UUID` identity newtypes serialize as canonical lowercase non-nil `UUID` strings (`management.rs:12` identity macro, `domain.rs:18` `CatalogId`). Native persisted paths are `EncodedPath`: `{encoding:"unix-bytes",bytes:[u8...],display:string}`. Bytes authoritative, display informational. Persisted paths absolute. Encoding other than unix-bytes or embedded `NUL` rejected. Configuration path strings must be UTF-8. Commit/tip fields are hexadecimal object-ID strings (40 or 64 characters when validated), branch/reference/checkpoint fields strings.
- `Option<T>` becomes `null` unless explicitly skipped. Context keys aren't universally mandatory. Handler indexing missing data fields can intentionally populate context with null. Catalog IDs in failure observation can also be null.
- Generic failure context `{}` and data `{next_action:string}`. `PoolExhausted` context `{repository_id}`, data `{maximum:u32,registered_count:usize,assigned_count:usize,next_action}`. Ordinary reasons map to rejected except `initialization_pending`/`catalog_relocation_pending`/`operation_pending` -> pending and `commit_unknown` -> unknown.
- `augment_catalog_receipt` adds important alternatives: pending/unknown catalog results or any `catalog_relocation_pending` result without `data.authority` receive context `{catalog_id,catalog_path,selected_catalog_path}` and **flattened `AuthorityObservation` fields in data**, plus `catalog_mutations_available`/`worktrees_moved`/`next_action`. `catalog_conflict` can add observed active context paths plus **nested** `data.authority`. Observation failure leaves the generic failure. Authority nesting depends on the observed variant.
- Diagnostic warning vocabulary presently only `diagnostic_listener_failed`. Warnings don't change outcome/reason/exit. Startup diagnostics sanitize direct stderr. `CommandObserved` stderr `JSON` fields command/outcome/`reason_code`/`catalog_id`?/revision? are diagnostic output, not another stdout result.

## Recovery response alternatives

- Unselected resource preview: `{repository_id,candidates:Candidate[],revision,next_action}`. Remaining resource context identities null. Candidate `{repository_id,worktree_id,path:P,assignment_handle:UUID|null,assignment:A|null,ownership,availability:"withheld",observation,next_action}`. Candidate ownership uses unassigned or serialized assignment state. This differs from `WV` ownership vocabulary.
- Assignment preview: `{observation,repository_id,worktree_id,assignment_handle,ownership:AssignmentState,availability:null|"withheld",assignment:A,next_action,revision}`. `operation_id` absent in data and null in context.
- Unassigned exact worktree preview returns Candidate directly, without revision field. Owned worktree preview returns assignment preview. Revision isn't present in every recovery response.
- Acquisition/creation/release operation preview: `{repository_id,worktree_id,assignment_handle,operation_id,operation:AcquisitionOperation|CreationOperation|ReleaseOperation,assignment:A,observation,ownership:AssignmentState,availability:null|"withheld",revision,next_action}`.
- Recovery result: `{observation,observed_assignment_handle:UUID|null,repository_id,worktree_id,assignment_handle:UUID|null,operation_id,operation:RecoveryOperation,ownership,availability:null|"retired"|"unverified"|"withheld",preservation_reference:string|null,preservation_tip:string|null,revision,next_action}`. Ownership unassigned or `AssignmentState`. Can remain active/preparing on completed outcome. Exact original IDs can select their recorded recovery result.
- Refresh/repository-recovery result: `{repository_id,worktree_id:null,assignment_handle:null,operation_id,operation:RefreshOperation|RepositoryRecoveryOperation,target_operation_id,target_refresh:RefreshOperation,ownership:null,availability:null,fresh_fetch_proven:bool,observed_commit:string|null,revision,next_action}`. Local `observed_commit` isn't proof of successful fresh fetch.
- Retirement preview: `{repository_id,worktree_id,operation_id,operation:RetirementOperation,retired:bool,ownership:"unassigned",availability:"retired"|"withheld",next_action}`. No revision/resources/`already_retired`. Apply uses retirement receipt (data revision absent in this recovery route. Only worktree retire adds it).
- Observation normal success `{safe:bool,tip:string,branch:string|null,reason_code:null|"preservation_unverified",preservation:[{reference,tip,verified:bool}]}`. Failed Git/safety observation `{safe:false,reason_code:PoolErrorReason,preservation:[...]}` with tip/branch absent. Historical retired observation `{status:"historical",safe:false,reason_code:"registration_retired"}` without preservation. Historical Candidate uses unassigned/retired ownership/availability with a null assignment and handle. It grants no current ownership.

Catalog bootstrap/storage-repair receipt: context `{catalog_id:UUID|null,catalog_path:P,repository_id:null,worktree_id:null,assignment_handle:null,operation_id:UUID|null}`. Successful data `{scope:"catalog",authority:AuthorityObservation,operation:CatalogRecoveryOperation|null,ownership:null,availability:null,catalog_mutations_available:bool,already_completed:bool,next_action}`. Failure uses nullable authority/operation and omits `already_completed`. `CatalogRecoveryOperation` = `AuthorityRecoveryFact` fields + scope:`"catalog"`,state:pending|completed,`last_checkpoint`:checkpoint,journal:`"active_catalog_locator"`. No revision field at top data. Authority has nullable revision. Preview can return completed even when authority bars mutations.

Relocation receipt: context `{catalog_id:UUID|null,catalog_path:P|null,selected_catalog_path:P,operation_id:UUID|null,repository_id:null,worktree_id:null,assignment_handle:null}`. Data `{authority:AuthorityObservation|null,operation:TechnicalRelocationOperation|null,worktrees_moved:false,retained_source:P|null,retained_source_bytes:u64|null,retained_source_bytes_checkpoint:"intended"|null,retained_source_active:bool,catalog_mutations_available:bool,next_action}`. `TechnicalRelocationOperation` = Relocation fields + scope:`"catalog"`,kind:`"relocation"`,state:pending|completed,`last_checkpoint`:Checkpoint,journal:`"catalog_cloud_events"`. Failures use same observed data plus error outcome/reason. No universal scope/ownership/availability keys.

Missing relocation-journal alternative: context **only** `catalog_id`,`catalog_path`,`selected_catalog_path`,`operation_id`. Data `{authority,operation:SemanticRelocationOperation,catalog_mutations_available:false,worktrees_moved:false,next_action}`. Operation has nested intent and no technical kind/scope/checkpoint/journal. Outcome pending/`catalog_relocation_pending`, or rejected/`selector_conflict` for conflicting scope.

## Serialized object inventory

All fields below present unless noted. Types `?` mean `JSON` null. Numbers are `JSON` integers, not strings. `revision/source_revision/last_release_position/position/bytes` use u64. Store/projection/`schema_version`/capacity use u32.

- `CP`: `catalog_id`,revision,`store_version`,`projection_version`,repositories:R[],worktrees:W[],operations:`RefreshOperation`[],assignments:A[],`withheld_worktrees`:`WithheldWorktree`[],acquisitions:`AcquisitionOperation`[],releases:`ReleaseOperation`[],creations:`CreationOperation`[],recoveries:`RecoveryOperation`[],`repository_recoveries`:`RepositoryRecoveryOperation`[],retirements:`RetirementOperation`[],relocations:`SemanticRelocationOperation`[],`catalog_stream_revision`?:u64 (**omitted**, not null when None).
- R: `repository_id`,`common_directory`:P,`context_path`:P,capacity,revision.
- W: `worktree_id`,`repository_id`,path:P,`git_directory`:P,`last_release_position`:u64?.
- Current `WV` W + `registration_state`,resources:`WorktreeUsage`,ownership,`assignment_handle`:`UUID`?,availability,`withheld_reason`:string?,creation:`CreationOperation`?,`pending_work`:O[]. Retired `WV` W + `registration_state`:`"retired"`,ownership:`"unassigned"`,availability:`"retired"`,retirement:`RetirementOperation`,resources:`RetiredUsage`. **doesn't add** `assignment_handle`/`withheld_reason`/creation/`pending_work`.
- A: `assignment_handle`,`operation_id`,`repository_id`,`worktree_id`,path:P,`resolved_commit`,branch:string?,state:`AssignmentState`.
- `WithheldWorktree`: `repository_id`,`worktree_id`,reason:string.
- `RefreshOperation`: `operation_id`,`repository_id`,state,`last_checkpoint`,`intent_event_id`,`resolved_commit`:string?.
- `AcquisitionOperation`: `operation_id`,`repository_id`,`worktree_id`,`assignment_handle`,state,`intent_event_id`,`last_checkpoint`,`preservation_tip`:string?,`preservation_reference`:string?.
- `ReleaseOperation`: `operation_id`,`repository_id`,`worktree_id`,`assignment_handle`,state,tip,branch:string?,`preservation_reference`:string?,`intent_event_id`,`last_checkpoint`.
- `CreationOperation`: `operation_id`,`repository_id`,`worktree_id`,`assignment_handle`,`acquisition_operation_id`,state,`last_checkpoint`,`intent_event_id`.
- `RecoveryOperation`: `operation_id`,`repository_id`,`worktree_id`,`assignment_handle`:`UUID`?,state,tip:string?,branch:string?,`preservation_reference`:string?,`intent_event_id`,`last_checkpoint`,`target_operation_id`:`UUID`?,disposition,`protected_reason`:string?.
- `RepositoryRecoveryOperation`: `operation_id`,`repository_id`,`target_operation_id`,`target_checkpoint`,state,`intent_event_id`,`last_checkpoint`,`observed_commit`:string?.
- `RetirementOperation`: `operation_id`,`repository_id`,`worktree_id`,worktree:W,`reconciliation_id`,`reconciliation_checkpoint`,state,`intent_event_id`,`last_checkpoint`.
- `SemanticRelocationOperation`: intent:`RelocationIntent`,state,`intent_event_id`,`completion_event_id`:string?. Intent `operation_id`,`catalog_id`,source:P,destination:P,`source_revision`.

Raw positioned record strings appear directly. They aren't decoded `CloudEvents`.

- `RelocationFact`: `schema_version`,position,relocation:Relocation.

## States and checkpoint vocabulary

These enums serialize as the following values. They differ from outcome aliases:

- `AssignmentState` preparing/active/released.
- `RefreshState` pending/completed/`needs_reconciliation`/reconciled. Checkpoints `intent_recorded`/`result_committed`/`fetch_failed`/`refresh_reconciled`.
- `AcquisitionState` reserved/`preservation_intended`/preserved/`checkout_intended`/completed/`needs_reconciliation`/reconciled. Checkpoints `reservation_committed`/`preservation_intended`/`preservation_committed`/`checkout_intended`/`acquisition_committed`/`checkout_uncertain`/`acquisition_reconciled`.
- `ReleaseState` intended/preserved/completed/`needs_reconciliation`/reconciled. Checkpoints `release_intended`/`preservation_committed`/`preservation_failed`/`release_committed`/`release_state_uncertain`/`release_reconciled`.
- `CreationState` reserved/`path_prepared`/completed/`needs_reconciliation`/reconciled. Checkpoints `creation_registered`/`creation_path_prepared`/`creation_committed`/`creation_uncertain`/`creation_reconciled`.
- `RecoveryState` intended/preserved/completed/`needs_reconciliation`. Disposition released/active/withheld/unassigned. Checkpoints `recovery_intended`/`recovery_preserved`/`recovery_committed`/`recovery_state_uncertain`.
- `RepositoryRecoveryState` intended/completed. Checkpoints `repository_recovery_intended`/`repository_recovery_committed`.
- `RetirementState` intended/completed. Checkpoints `retirement_intended`/`retirement_committed`.
- Semantic `RelocationState` pending/completed. Technical Checkpoint starting/intended/prepared/switched/committing/completed. Technical and semantic states are distinct.
- Authority phase active/initializing. `store_state` validated/`rebuild_required`/unreadable/missing. `last_checkpoint` `recovery_intended`/`authority_published`/`store_committed`/`intent_recorded`. Recovery checkpoint `intent_recorded`/completed.
- `WV` `registration_state` registered/missing/unreadable/mismatched/retired. Ownership unassigned/assigned/preparing. Availability unverified/withheld/retired. Recovery ownership uses unassigned/preparing/active/released instead of assigned. Null availability is historical/non-applicable, not free capacity.
- `WV` `withheld_reason` registration-state failures, owned, `operation_pending`, persisted `WithheldWorktree.reason`, or null. Acquisition persisted reasons `retained_file_collision`/`unfinished_work`/`git_operation_in_progress`/`unsupported_index_state`/`safety_uncertain`. Recovery `protected_reason` additionally `partial_creation_unproven`. Observation reasons additionally `preservation_unverified`/`registration_retired`.

## Resources: shapes and nested reason vocabulary

- `WorktreeUsage` `{metric:"logical_regular_file_bytes",worktree:Measurement,known_external_build_state:External,shared:{bytes:null,status:"reported_by_repository_inspection",reason_code:"shared_git_storage_not_worktree_exclusive"},unknown:Unknown[],exclusive_bytes:false,capacity_semantics:"registered_count_not_byte_limit"}`.
- `RetiredUsage` same except worktree unavailable status `retired_path_unattributed` and `shared.reason_code` absent.
- `RepositoryUsage` `{metric,worktree_bytes:u64|null,worktrees:[{worktree_id,usage:Measurement}],shared:Measurement,known_external_build_state:External,unknown:Unknown[],aggregation:"unique_device_inode_across_report_roots_common_directory_first",exclusive_bytes:false,capacity_semantics}`. Common storage measured first. Hard-linked identities deduplicated, separate worktree reports not additive.
- Measurement success/partial `{path:P,bytes:u64|null,measured_bytes:u64,status:"measured"|"partial",unmeasured_paths:[{path:P,reason_code}],git_metadata_excluded:bool,symlinks_followed:false}`. Unavailable `{path:P,bytes:null,status}` only. Status `invalid_path`/`retired_path_unattributed`/`unsafe_root`/missing/unavailable. Null != zero.
- Skipped traversal reasons `metadata_unavailable`/`symlink_or_mount_not_followed`/`directory_unavailable`/`special_file_unmeasured`.
- External `{bytes:null,status:"unmeasured",reason_code:"no_authoritative_build_state_roots",explanation}`. Unknown array `{bytes:null,reason_code:"external_build_state_unmeasured"|"physical_usage_unmeasured",scope}`. These nested reasons aren't top-level error outcomes.

## Top-level reason vocabulary, version 1

- Completed: `ok`,`already_released`,`already_retired`,`recovery_observed`,`catalog_recovery_observed`,`catalog_recovery_completed`,`catalog_recovery_already_completed`,`catalog_relocated`,`catalog_relocation_observed`,`catalog_relocation_completed`,`catalog_relocation_already_completed`.
- Pending: `initialization_pending`,`catalog_relocation_pending`,`operation_pending`,`refresh_failed`. Pending refresh directly returns the last code.
- Unknown: `commit_unknown`.
- Rejected: `invalid_arguments`,`invalid_configuration`,`catalog_missing`,`catalog_exists`,`catalog_conflict`,`catalog_corrupt`,`unsupported_version`,`unsafe_permissions`,`filesystem_error`,`storage_error`,`git_failed`,`resource_unregistered`,`selector_conflict`,`capacity_exhausted`,`capacity_below_count`,`capacity_zero`,`capacity_all_assigned`,`capacity_no_safe_worktree`,`worktree_unavailable`,`retained_file_collision`,`unfinished_work`,`git_operation_in_progress`,`unsupported_index_state`,`assignment_unknown`,`retirement_preconditions_unmet`.
- `capacity_zero` is maximum=0. `capacity_all_assigned` is `registered_count`==`assigned_count` after zero case. Otherwise `capacity_no_safe_worktree`. Reasons don't universally carry the same context/data or imply availability. Human `next_action`/explanation/scope text is guidance rather than a stable machine vocabulary.

## Events list: the public typed payload union

`CloudEvent` object fields `specversion`:`"1.0"`,id,source:`"urn:uuid:<catalog-id>"`,type,subject,time:`UTC` `RFC3339`,datacontenttype:`"application/json"`,operationid:string, optional causationid:string, data. `catalog.initialized.v1` data is `{catalog_id,store_version,projection_version}`. Other data is serde tagged `{kind,record}`. Nested workflow event record is itself `{kind,record}`. Thus document nested tags, not only type strings. Storage keeps stream positioning/expected revisions as metadata rather than adding them to events list objects.

Type suffixes all prefixed `io.lowkeylab.worktreepool.`. Outer kind -> record:

- `repository.registered.v1`: `repository_registered` -> R. `worktree.registered.v1`: `worktree_registered` -> W. `worktree.registered.v2`: `worktree_enrolled` -> W. `repository.capacity.configured.v1`: `capacity_configured` -> `{repository_id,maximum}`. `worktree.withheld.v1`: `worktree_withheld` -> `WithheldWorktree`. `repository.refresh.started.v1`: `refresh_started` -> `{operation_id,repository_id}`. `repository.refresh.finished.v1`: `refresh_finished` -> `{operation_id,repository_id,resolved_commit?}`.
- Outer acquisition: `assignment.reserved.v1` inner reserved:A. `worktree.preservation.intended.v1` `preservation_intended`:{`operation_id`,`repository_id`,`worktree_id`,tip}. `worktree.preserved.v1` preserved and `worktree.checkout.intended.v1` `checkout_intended`: same identities. `assignment.acquisition.finished.v1` finished: same identities + successful:bool.
- Outer release: `assignment.release.started.v1` started:`ReleaseOperation`. `assignment.release.preservation.finished.v1` `preservation_finished` and `assignment.release.finished.v1` finished: `operation_id`,`repository_id`,`worktree_id`,successful.
- Outer creation: `worktree.creation.registered.v1` registered:{`operation_id`,worktree:W,assignment:A}. `worktree.creation.path.prepared.v1` `path_prepared`:{`operation_id`,`repository_id`,`worktree_id`}. `worktree.creation.finished.v1` finished: same identities + successful.
- Outer recovery: `recovery.started.v1` started:`RecoveryOperation`. `recovery.preserved.v1` preserved:{`operation_id`,`repository_id`,`worktree_id`}. `recovery.finished.v1` finished:same identities + successful.
- Outer `repository_recovery`: `repository.recovery.started.v1` started:`RepositoryRecoveryOperation`. `repository.recovery.finished.v1` finished:{`operation_id`,`repository_id`,`target_operation_id`,`observed_commit`?}.
- Outer retirement: `worktree.retirement.started.v1` started:`RetirementOperation`. `worktree.retirement.finished.v1` finished:{`operation_id`,`repository_id`,`worktree_id`}.
- Outer relocation: `catalog.relocation.started.v1` started:`RelocationIntent`. `catalog.relocation.completed.v1` completed:{`operation_id`,`catalog_id`}.
