# Task 3: Discord operational audit boundary

## Result and changes

Implemented the narrow public `InteractionTransport` boundary with private Serenity adapters for commands, modals, and components. Slash and modal writes and the PostgreSQL integration entrypoint use the same deferred-response orchestration and real store execution. Components retain initial-response semantics and never defer.

The store listener now receives separate acknowledgement/delivery outcomes, final query outcomes (including the bounded component timeout), input/form rejection events, registration outcomes, grant discovery failures, and the existing lifecycle signals. Removed the unconditional command ERROR log: the store remains the sole owner of final command outcomes. All audit inputs use safe typed categories and canonical numeric interaction IDs. Private responses, mention suppression, receipt recovery, transaction behavior, and existing shutdown scheduling are preserved.

The public addition is only `execute_interaction` and the transport trait; Handler and concrete Serenity adapters stay private. The read seam accepts the actual read future and optional deadline. Production supplies `Store::view` and the existing two-second component limit. Tests use a pending future and zero deadline without sleeps or elapsed-time assertions. Tests never inspect rendered diagnostic logs or JSON log output; JSON assertions concern the existing Discord response/wire contract only.

The grant continuation regression now corrupts the first discovered guild and verifies a later healthy guild still receives its grant, so changing `continue` to `break` can no longer evade the test by processing the healthy guild first.

Parent review required preserving the original shutdown diagnostic distinctions. Added only four Stage values: ShutdownRequested, GatewayShutdown, GrantWorkerShutdown, and GatewayLockRelease, retaining Shutdown for the final stopped outcome. These labels preserve existing operational context without changing recovery or shutdown control flow. No enum-construction or rendered-output tests were added.

## Coverage and fidelity

- **PostgreSQL write/delivery tests:** integration scope; mixed state/output/communication assertions. Each test uses its own real PostgreSQL container and application-owned schema. The only substitute is the outgoing unmanaged Discord transport: it returns acknowledgement input and records response builders without implementing economic behavior. Balance, persisted receipt, one bet after duplicate delivery, matching command-success/delivery-failure events, and no mutation on failed acknowledgement are observed. Regression protection is demonstrated by the intended RED/GREEN sequence; refactoring resistance is inferred from public outcomes and shared production orchestration rather than private helper-call expectations. Runtime is measured above.
- **Controlled HTTP composition tests:** integration checks of the actual private production handlers and concrete Serenity adapters against a per-test local Axum endpoint. They observe POST callback/PATCH original-response paths, ephemeral acknowledgement, preserved safe response bodies, component initial-response semantics, actual `Store::view` failure from a closed real SQLx pool, registration success, validation rejection, and safe status/code-only delivery events. The endpoint returns a real 40060 HTTP error and the production handler still performs the read and attempts delivery; acknowledgement is recorded as successful recovery. Real HTTP 503 with sentinel provider text produces only the allowlisted Discord category/status/code. PostgreSQL persistence is covered separately, not simulated in these endpoint tests.
- **Read deadline/classification tests:** small isolated output-based checks through the production read orchestration. Pending future with zero timeout tests timeout behavior deterministically. Tests assert safe responses and typed correlated events, not elapsed time. Success, database configuration failure, and corrupt-history rejection classification remain distinguishable. The initial missing-query-events regression was demonstrated before emission implementation.
- **Worker discovery test:** actual grant worker plus a closed SQLx pool. A test-local listener records the typed discovery failure and signals shutdown through the existing watch channel; no scheduling sleeps or worker redesign. The real worker exits normally after emitting the safe connection category.

Remaining fidelity gaps: no live Discord API/gateway connection, gateway lifecycle signal/timeout integration, or production log collection/retention behavior was tested. Local endpoints establish pinned-client request and error handling, not live-provider compatibility. The slash creation-menu read uses the existing Component query category.
