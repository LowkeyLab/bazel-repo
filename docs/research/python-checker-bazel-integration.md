## Provider compatibility

rules_py libraries, binaries, and tests publish `PyInfo` imported from `@rules_python//python:defs.bzl`. That export aliases `python:py_info.bzl`, the same provider used by rules_mypy. This establishes source-level provider compatibility without migrating first-party rules. The selected provider supplies empty `direct_pyi_files` and `transitive_pyi_files` defaults, so ty's unguarded access to the latter is supported at these pins. [Library](https://github.com/aspect-build/rules_py/blob/v1.12.1/py/private/py_library.bzl), [binary/test](https://github.com/aspect-build/rules_py/blob/v1.12.1/py/private/py_binary.bzl), [provider export](https://github.com/bazel-contrib/rules_python/blob/192b1c2dd72d0e42136bcbe6e44ffad0f354d620/python/defs.bzl), [provider defaults](https://github.com/bazel-contrib/rules_python/blob/192b1c2dd72d0e42136bcbe6e44ffad0f354d620/python/private/py_info.bzl).

The shared pytest wrapper preserves authored `srcs`, supplies pytest, and selects the upstream shared pytest entrypoint. The underlying rules remain `py_test`, as the query confirms. A type-checking aspect can therefore inspect authored tests directly; executing pytest is unnecessary. Both libraries declare `imports = ["."]`, giving independent import roots in `.github/scripts` and `python_sample`. [Wrapper](https://github.com/LowkeyLab/bazel-repo/blob/de1b8f8507d476d9c44ef608a1c298bef1b6c055/tools/python/defs.bzl), [pytest macro](https://github.com/aspect-build/rules_py/blob/v1.12.1/py/defs.bzl), [import propagation](https://github.com/aspect-build/rules_py/blob/v1.12.1/py/private/pth.bzl).

## Integration choices

| Approach             | Existing support                                                                                           | Remaining integration work                                                                                                                   |
| -------------------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| mypy with rules_mypy | Shared PyInfo, own/transitive import roots, dependency runfiles, stub mapping, upstream incremental caches | Supply a current compatible checker; bridge results into Aspect lint or deliberately use action failure; verify behavior under the lint task |
| ty with rules_lint   | Existing `lint_ty_aspect`, normal lint reports, transitive sources/search paths, configurable arguments    | Provision ty in the actual tool hub; decide strict annotation policy; verify own import roots, exclusions, and dependency metadata           |
| Pyright family       | No corresponding aspect in the inspected rules_lint source tree                                            | Custom lint aspect/runner, pinned checker and execution runtime, project/search-path configuration and declared dependency inputs            |

### mypy

The pinned aspect visits first-party PyInfo targets with Python `srcs`, propagates over `deps`, and supports global configuration and a dependency-to-stub mapping. It collects dependency runfiles and the target's own import roots. However, it emits only the `mypy` output group and directly fails its action on checker errors. It does **not** implement the `rules_lint_human`/`rules_lint_machine` report contract. Adding its aspect name alone is therefore not evidence of a complete Aspect lint integration. A hard action failure could enforce errors, but reporting and successful execution still need explicit acceptance. [Aspect](https://github.com/theoremlp/rules_mypy/blob/9f56e973b5a30391afba51e1726b0c6638da024d/mypy/private/mypy.bzl).

Its bundled checker is **mypy 1.17.1**, running in a separate Python 3.12 environment. Do not confuse that with a newly researched checker release or assume it checks the selected interpreter. `mypy_cli` and the aspect accept replacement dependencies/executables. A repository-owned Bazel executable using the accepted shared uv hub is a candidate; no host pip installation is required. The checked Python version must be explicit and follow the interpreter policy. [Pinned requirements](https://github.com/theoremlp/rules_mypy/blob/9f56e973b5a30391afba51e1726b0c6638da024d/mypy/private/requirements.txt), [module provisioning](https://github.com/theoremlp/rules_mypy/blob/9f56e973b5a30391afba51e1726b0c6638da024d/MODULE.bazel), [CLI override](https://github.com/theoremlp/rules_mypy/blob/9f56e973b5a30391afba51e1726b0c6638da024d/mypy/private/mypy.bzl).

The runner merges dependency cache directories into its output cache, forces incremental mode, and skips cache mtime checks. Config, sources, dependency runfiles, and upstream caches are action inputs; Bazel action caching and mypy incremental caching are separate mechanisms. The action also inherits `ctx.configuration.default_shell_env`; review that effective environment rather than claiming perfect hermeticity from source alone. [Runner](https://github.com/theoremlp/rules_mypy/blob/9f56e973b5a30391afba51e1726b0c6638da024d/mypy/private/mypy_runner.py), [action declaration](https://github.com/theoremlp/rules_mypy/blob/9f56e973b5a30391afba51e1726b0c6638da024d/mypy/private/mypy.bzl).

### ty

The pinned rules_lint already contains `lint_ty_aspect`. It checks each target's sources, declares dependency `transitive_sources`/`transitive_pyi_files`, config and tool inputs, propagates over `deps`, and emits human and machine reports with recorded exit status. Its config, arguments, tools, and transitive inputs participate in action invalidation; config changes invalidate all affected actions. This is the smallest existing reporting integration of these options. [Pinned ty aspect](https://github.com/aspect-build/rules_lint/blob/c602583358226de5cad887a3e1887c0c02c9500c/lint/ty.bzl).

Three caveats need acceptance. First, the `ty_bin` alias points at `@multitool//tools/ty`, but this repository supplies its own multitool hub and its lock has **no ty entry**. The alias alone does not provision the tool. Second, the aspect constructs search paths from dependency providers, not the target's own `PyInfo.imports`; own custom import roots need a focused check. Third, it passes `--force-exclude`, so explicit target files can still disappear through checker configuration. [Alias](https://github.com/aspect-build/rules_lint/blob/c602583358226de5cad887a3e1887c0c02c9500c/lint/BUILD.bazel), [actual tool lock](https://github.com/LowkeyLab/bazel-repo/blob/de1b8f8507d476d9c44ef608a1c298bef1b6c055/tools/tools.lock.json), [hub override](https://github.com/LowkeyLab/bazel-repo/blob/de1b8f8507d476d9c44ef608a1c298bef1b6c055/MODULE.bazel).

### Shared custom integration requirements

A custom adapter should use the existing lint output contract, an execution-configured Bazel executable, explicit configuration and checked Python version, authored source inputs, transitive Python/stub inputs, and provider-derived import roots. Include stub packages and `py.typed` metadata rather than only `.py` files. rules_py unpacked wheels expose their complete directory as `PyInfo.transitive_sources` and runfiles, which can carry bundled metadata; a runner must actually resolve that layout. Direct first-party `pyi_srcs`/`pyi_deps` generation is disabled under the accepted release, so external stub packages need an explicit compatible route. [Wheel provider](https://github.com/aspect-build/rules_py/blob/v1.12.1/py/private/py_unpacked_wheel.bzl), [Gazelle directives](https://github.com/LowkeyLab/bazel-repo/blob/de1b8f8507d476d9c44ef608a1c298bef1b6c055/BUILD.bazel), [lint contract](https://github.com/aspect-build/rules_lint/blob/c602583358226de5cad887a3e1887c0c02c9500c/lint/private/lint_aspect.bzl).

## Coverage and acceptance

CI currently runs `aspect lint //...` with an explicit aspect list. Adding the chosen type-checking aspect there covers discovered matching targets, including today's `.github` packages, without hand-listing future target labels. It does not automatically cover arbitrary future files. `no-lint`, unmatched rule kinds, generated-source filtering, ignored directories, absent BUILD targets, Gazelle exclusions, and checker exclusions remain escape paths. The standard rules_lint helper skips `no-lint` and normally checks only first-party source files; generated files require `lint-genfiles`. rules_mypy separately supports `no-mypy` and optional opt-in tags. [Task configuration](https://github.com/LowkeyLab/bazel-repo/blob/de1b8f8507d476d9c44ef608a1c298bef1b6c055/.aspect/config.axl), [CI](https://github.com/LowkeyLab/bazel-repo/blob/de1b8f8507d476d9c44ef608a1c298bef1b6c055/.github/workflows/run-tests.yml), [filters](https://github.com/aspect-build/rules_lint/blob/c602583358226de5cad887a3e1887c0c02c9500c/lint/private/lint_aspect.bzl).

Proposed implementation acceptance should:

- Compare tracked first-party Python files with discovered checked target sources, including tests and hidden directories; require documented narrow exceptions for any gap.
- Introduce representative type errors in a library, binary, and test, including `.github/scripts`; verify the existing local and CI lint command fails, then remove the errors.
- Verify strict missing-annotation handling, local imports through both existing import roots, pytest annotations, packaged dependency typing and a stub-only dependency.
- Verify a newly generated target enters coverage without editing an allowlist. Check `data`-only Python and unsupported/ignored directories explicitly.
- Run from an isolated sandbox without host packages; verify changed source, imported dependency, stub, config, checker binary, and interpreter selector invalidate the relevant action. Distinguish a Bazel cache hit from a checker incremental-cache hit.

These are proposed checks, not results from this research. No migration, checker selection, or strictness exception is approved by this note.
