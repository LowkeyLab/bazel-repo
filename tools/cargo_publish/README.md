# Cargo publishing inputs

Load `cargo_publish` from `//tools/cargo_publish:defs.bzl`. Declare explicit
package metadata and select a Rust library with sources declared beneath the publishing package directory:

```starlark
cargo_publish(
    name = "publish",
    library = ":library",
    package_name = "example-package",
    version = "0.1.0",
    description = "An example library",
    license = "MIT",
    repository = "https://github.com/LowkeyLab/bazel-repo",
    rust_version = "1.96",
    readme = "README.md",
    package_files = {
        "README.md": "README.md",
        "LICENSE": "LICENSE",
    },
)
```

Run `nix develop --command aspect build //path/to/package:publish_files`.
The outputs are `publish_files.package/` and `publish_files.json` under
`bazel-bin/path/to/package/`. The tree contains the standalone Cargo manifest,
declared Rust sources, and explicitly mapped assets. The JSON generation
contract sits beside the package tree. Cargo doesn't include it as a publishing asset.

Generation uses configured Rust providers and an aspect to obtain library
name, edition, root, direct dependency aliases, exact versions, and enabled
features. It joins the configured direct dependencies to declared upstream
Cargo metadata and the root Cargo manifest and lockfile. Dependency identity
must originate in the root `crates` repository generated by the pinned
`rules_rs` extension, with unambiguous crates.io lock provenance. Requested
default and explicit features reflect configured Bazel activation. The
publisher maintains no separate dependency list or feature overrides.

Generation reads only declared inputs and requires no registry access.
Sources retain paths relative to the publishing package directory. Each
`package_files` label must identify one existing source file, mapped to a
relative package path. Map the required readme, compilation data, and production data explicitly.
Conflicting, reserved, and escaping paths fail with target/path diagnostics.
The generator rejects generated sources, publisher features and build scripts,
compiler flags, environment inputs, separate local packages, and source modifications
requiring Cargo translation. The initial slice supports a library for
`x86_64-unknown-linux-gnu`. Binary and development dependency declarations fail
explicitly until their generation slice lands.

The root Cargo manifest and lockfile remain unchanged. Generation writes no
consumer lockfile and doesn't participate in ordinary Rust compilation.
Cargo owns transitive resolution during the subsequent validation workflow.

## Generation contract

`CargoPublishInfo` is the public analysis provider. `package` is the staged
tree artifact. `contract` is the accompanying JSON file. Validation rules can
consume these fields without discovering source files or reading the checkout.

Contract schema version `1` includes:

- `package`: explicit metadata, edition, and readme path.
- `target`: configured Rust target triple.
- `library`: selected target label, crate name/type, edition, and staged path.
- `binaries` and `tests`: reserved arrays for the following generation slice.
- `dependencies`: direct target/package/version/source/checksum identity,
  Cargo alias, dependency kind, enabled feature names, and `default_features`.
- `inputs`: declared package paths, byte lengths, and SHA256 fingerprints.
- `manifest_sha256`: fingerprint of the generated original Cargo manifest.
- `provenance`: fingerprints of the root manifest, lockfile, and module settings.

Identical selected inputs produce identical trees and contracts. The generation
contract describes declared inputs. A later archive validation report must
establish verified package status separately.

The public generation command is `//tools/cargo_publish:generate`. Its required
arguments are `--spec`, `--root-manifest`, `--root-lockfile`, `--module`,
`--output`, and `--contract`. The macro supplies the analysis specification.
Command fixtures exercise rejection diagnostics and deterministic generation
with explicit inputs. Run the offline contract suite with
`nix develop --command aspect test //tools/cargo_publish/...`.
